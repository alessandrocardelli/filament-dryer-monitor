### New Sanwa measurement timing aid — ONLY an operator prompt, never a safety function

- New `firmware/SanwaReminder.h`, existing `Buzzer.h` and `Ui.h`: after explicit START, one short **1650Hz/110ms** reminder at elapsed **1 through10 minutes, every minute**, then at elapsed **12,14,16... minutes, every2 minutes** (including thermal holds). This is a sample schedule, NOT a heater ON/OFF limit. No buzzer `delay()` or extra MCU hardware timer, so ISR deadline remains unchanged.
- On explicit manual STOP **or** normal user-timer completion, the Sanwa sample timer restarts independently at **+30,+60,+90,+120 seconds relative to the STOP/COMPLETE transition**. These are not timestamps since a previous thermostat/OFF pulse. After +120 seconds the reminder turns off and final CSV can be saved. **On FAULT, cancel reminders immediately, retain fault sound and independent thermal protection**; no post-fault measurement beeps.
- Before measurement ensure user `SETTINGS > BUZZER` volume is **LOW, MED or HIGH** (OFF suppresses prompts). The beeps never preempt another sound: if the start/finish/fault chime is currently playing, the reminder defers until the buzzer becomes idle. Faults always have higher priority.
- In the live DRYING screen press **MODE short** to switch to the technical page; header reads `SANWA NEXT mm:ss`, with AIR/NTC/fan/heater indications below. MODE short again returns to the main temperature/status page. In normal COMPLETE the screen shows the next post-cycle Sanwa countdown. In STANDBY after manual STOP, acoustic poststop reminders work even though the standard standby page is displayed. The Sanwa readings are **still manual**.
- MCU records `SANWA_READ @ms=<device uptime>` on Serial and writes a forced *RAM-only* thermal CSV sample at each cue, aligning physical manual Sanwa readings with the usual AIR/NTC/HEATER timestamp without flash writes during HEATER. The user enters the Sanwa °C in the already created [one-sheet Sanwa register](https://docs.google.com/spreadsheets/d/1I5utkzGP1zvD168jLghpYB_y_myGjxMb1ccLens4Cks/edit) (start minute or poststop event). The early original schedule, which required a separate external stopwatch, is superseded by these same prompt times.
- New identity `HOT-261030-SANWA` and `H30-SNW`; core ESP32 full compile and host tests must pass before uploading. **Scope of diff: buzzer/UI/logging/operator workflow only.** Existing AIR40–55°C targets, NTC9.81/13.73/7.12kΩ, AIR fault60°C, max ON20s/ISR20.5s, minOFF2s, FAN100, postheat fan90s and TCO105 unchanged.
